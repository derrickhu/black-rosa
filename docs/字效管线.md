# 墨弹防线 · 字效管线

> 加字只填定义，不新开一套 if/else。26 字全部挂在这套槽位上，新字对号入座。
> 玩法锁：一字一牌；常驻 / 蓄力 / 词组；三行一列；母弹进列计数；成词后常驻仍可叠。
> 本文是**实现后的回写**，第 5 / 6 节的数字就是 `Assets/Scripts/Data/GlyphDef.cs` 里的值，改代码要同步改这里。

## 1. 总原则

1. **效果按槽位叠，不按「这对元素有没有专图」叠。** 同槽取强（Max / 后写覆盖），异槽全保留。
2. **伤害是一条管子，状态是另一条管子。** 「本身无伤害」只表示这个字不改伤害数字，不阻止它给弹上状态。
3. **表现也是槽位。** 炮弹最多同时亮 5 层：体 / 尾 / 环 / 绕 / 晕光。颜色可以叠，形不能抢同一层。
4. **两两三三不画专图。** 8 元素两两 28、三三 56，小游戏养不起。新鲜感来自层叠，只给 12 对「招牌两两」换一张体图。
5. **星级：★1 身份，★2 加数，★3 才允许多一个动词。** 冰（缓→冻）就是标准。不要每个字 ★3 都变一个新玩法。

## 2. 五个家族

| 家族 | 管的是 | 字 |
|---|---|---|
| 伤 Hurt | 数字怎么算 | 金（加算）、重（乘算）、木（吸血） |
| 状 Status | 打上以后留在人身上 | 火、毒、冰、水、雷、晕、惑 |
| 位 Move | 把人挪开 | 土（沿列）、风（换列）、击退（词） |
| 道 Ballistic | 弹怎么飞 | 分、瞄、速、穿 |
| 域 Area | 这一击波及谁 | 炸、万箭（词）、连斩（词） |

一个字只主属一个家族，可以带一个「骑手」（火★2 击杀掉小爆，冰★3 带冻）。骑手不能再开第三家族。

## 3. 命中结算十步（所有字共用）

直击、溅射、连斩、落箭都进 `BattleWorld.ResolveHit(e, mods, src, from)`，`from` 区分来源。
溅射 / 万箭 **关掉斩杀**，避免一圈全斩；域伤害不再触发域，避免自激。

```
0  盾：普通弹只破盾就停；斩杀破盾后继续
1  斩杀（最高，仅 Direct）：非头目 HP→0；头目按最大生命比例
2  基础弹伤 × 道族衰减（穿透每穿一个 ×0.85，分裂每股 ×0.6，溅射 ×0.6，连斩每跳 ×0.75）
3  伤族加算池求和（金）
4  伤族乘算池连乘（重，最后）
5  木：不改打出的血，把结算总量按比例记入吸血池
6  扣 HP
7  状族：灼烧 / 毒 / 缓 / 冻 / 晕 / 惑
8  位族：土沿列上推；风横向换列
9  域族：炸圈、连斩跳、万箭落（不再走斩杀，也不再触发域）
```

**第 3 / 4 步的顺序是 `伤 × 乘算 + 加算`，加算默认不吃乘算。** 这条不是笔误：如果加算天然吃乘算，招牌「镇金」（金+重）就没有内容了。镇金亮起时才变成 `(伤 + 加算) × 乘算`。

### 六条叠加规则

1. **加算先求和，乘算最后连乘。** 两个池互不干涉。
2. **状态同名取强**（DPS 与时长各自 Max，减速取移速系数的 Min）。**毒是唯一可叠层的**，层数上限吃字的星级。
3. **硬控同时只生效一个**，优先级 `冻(3) > 晕(2) > 惑(1)`。输的那个降级成等时长的「缓」（移速 ×0.5），不白打。见 `GlyphTable.HardRank`。
4. **位移同轴取最大，异轴都执行。** 土和击退都是沿列，取远的那个；风是横向，和它们同时生效。
5. **域伤害不再触发域。** 炸圈里打死的人不会再炸一次。
6. **12 张招牌两两只改表现 + 一条小加成**，不动上面这十步。

晕自带防连晕：一次晕结束后 `时长 + 0.35s` 内免疫下一次硬控。

## 4. 四类表现规格

### 4.0 特效美术方向：平涂 · 鲜明 · 硬边 · 少层次

全部元素弹、道族 / 词组弹体、以及怪身上的六种状态层都已按这个方向出完。三条硬规则：

1. **一个特效最多 3～4 档纯色，档与档之间硬过渡。** 不要喷枪渐变、不要外发光、不要半透明烟雾。
2. **最外一档必须是深色（火是深红棕），它就是描边。** 战场底是米色宣纸 `#F4EFE4`，黄橙这种亮色和纸的明度差太小，没有深色外沿就会糊进背景 —— 旧版那颗柔光火球看不清正是这个原因。反过来也不要真给火焰加黑墨线，发光体镶黑边会变贴纸。
3. **层数要砍。** 旧版一发弹叠十层（核 / 弹丸 / 柔光 / 热点 / 体 / 环 / 两个绕 / 两条色带），硬边全被泡软。自带配色的图独占体槽，柔光层只在「混了两种以上元素」时才亮，用来说明这发弹还带着别的字。

4. **元素靠形状分，不靠颜色分。** 六个元素弹的剪影必须两两认得出来：火是圆球带火尾、冰是多面棱晶、水是光滑水滴、毒是带滴的瘤状团、土是带棱的石块、炸是暗球顶着火花。只换颜色的话，色盲玩家和缩小到子弹尺寸后都分不清。
5. **道族 / 词组一律墨黑 + 骨白 + 一点朱砂，不给元素色。** 「不带色」本身就是信息：一眼能分出「这是招式，不是元素」。同理它们**不吃星级渐变**（星改的是威力和动词，不是热度），每个只出一帧。

这类图走**普通混合**（`InkFx.PaintSprite` / `Sprites/Default`），不是黑底加法，所以也**不过** `vfx_crush.py`。

出图与切图：`docs/prompt/vfx/build_v2_prompts.py` 按共用的风格骨架批量生成 prompt（别再一份份重写风格块），`docs/prompt/runtime/vfx_flat_slice.py` 按作业表切帧去背。去背是从画布四边洪泛填充 —— 深色外沿会挡住填充，被包住的白热核因此留得下来。环和水纹那类图**中间的白进不去**，会留成实心白块，所以 `holes=True` 会把「被包住且超过主体包围盒 6%」的白块也挖掉，小块（白热核、气泡高光）留着。

`docs/prompt/runtime/vfx_preview.py` 按代码里的真实常量离线拼等比例预览图。编辑器窗口不聚焦时基本不推帧，实机截图不好拿，改了摆位常量就跑它对一眼。

**平涂体一概不染色**（`Body(..., Color.white)`）。原来会往混色偏 0.22，那会把招牌两两逐档定好的配色糊掉 —— 燎毒的绿火、雷决的靛紫电弧正是它们的身份。

**父级的非等比缩放要除掉。** 弹体节点被穿拉成 0.68 × 1.32、呼吸再叠一层反向挤压，那是给旧的柔光墨点设计的（软球压扁看不出）。硬边图压扁就是个蛋，所以 `InkShot.Undistort` 把长宽比除掉只留总体大小。穿的「细长」本来由 `pierce_shot` 那根长针自己说，不需要再挤弹体。

**`Scale` 是按「★1 弹头 0.139 世界单位」归一算出来的，不是拍的**：各元素弹头占精灵的比例差一倍多（冰 0.23、毒 0.48），只按精灵高归一会大小不一。词组那六个是按**旧柔光图的实际可见高**折算的 —— 新图紧裁无留白，照旧的 `FormScale` 给会凭空大一圈。

**八帧是一条「越往后越大越浓」的单调渐变，星级决定窗口落在渐变的哪一段**：★1 播 00–02，★2 播 03–05，★3 播 05–07。两条约束缺一不可 ——
整段 0–7 一起播会让高星缩回低星那几帧；而渐变必须**严格单调**，否则窗口跨在缩回处时会在两种形态间来回跳，看着像闪帧而不是升级。同屏的弹按 `b.Id` 错开相位。

单调这条得**量**，不能靠看：毒第一版前四帧宽度完全相同、第五帧还缩回去（★1 比 ★3 还大），重出了一版才对；土出成了 16 级但不严格递增，量过之后取 `[0,1,2,5,6,7,10,11]` 这 8 格（弹头宽 160→307 px，步长最匀），隔一格取会在第 3 格缩回去。

这类图**不能开块压缩**，深色外沿会崩出脏点，`InkArtImporter` 里按文件名走 `flatVfx` 例外（`_shot_` / `burn_body_` / `ice_crust_` / `dot_`）。`_shot_` 里那两条下划线是有意的 —— 它要排除旧的柔光单图 `shot_ice.png`。

**改了 `InkArtImporter` 就得让贴图重导一次**，否则新图还是被旧规则导进来的（压缩开着）。改导入器之后把 PNG 用 `Image.open(p).save(p, optimize=True)` 重存一遍：文件字节变了、像素不变，Unity 才会重导。查 `.meta` 里第一个 `textureCompression`，0 才是未压缩。

#### 元素小卫星：让「叠了几个字」数得出来

混色是**均色**，三个元素混完反而看不出是三个 —— 越叠越糊是它的固有毛病。所以叠字的读数改由 `ShotView.Motes` 承担：**体槽那张图没表达到的元素，各挂一颗纯色小圆绕着弹体转**（`InkFx.Mote`，实心亮面 + 一圈深色外沿，硬边）。元素最多 3 个，所以最多 2 颗。

判定规则在 `ShotLook.Motes`，按体槽图**画进去了哪些元素**来排：

| 体槽是 | 排掉 | 结果 |
|---|---|---|
| 单元素（火） | 它自己 | 火 → 0 颗；火+风 → 1 颗；火+风+金 → 2 颗 |
| 招牌两两（霜火） | 那一对 | 霜火 → 0 颗；霜火+雷 → 1 颗 |
| 词组 / 道族 | 一个都不排（那张图不带元素色） | 有几个元素就挂几颗，上限 2 |

于是升级阶梯是单调的：★1 小 → ★3 大 → +1 颗 → +2 颗 → 招牌专图（更大更繁）→ 专图 + 1 颗。跑 `vfx_preview.py combo` 能看到这条阶梯。

平涂体因此**一概不垫柔光**了（只留重 / 金的晕光槽，那是另一件事）。原来「混了两种以上元素就垫一圈柔光」是想表达同一件事，但柔光既泡软硬边又数不出个数。

#### 拖尾：跟着子弹，不留残留

拖尾是 `TrailRenderer`。三处都会让它在纸上留下一道脏影，是一起犯的：

1. **柔光材质**（`SoftMat`）。改成普通混合（`SpriteMat`）—— 柔光叠得越久越亮，正是「子弹过后留了脏」的样子。
2. **软贴图**。`StreakTex` 原来横向是 sigma 3.4 的高斯，在 16px 高上几乎糊满整条。改成满宽实心、只留一格收边。
3. **时长太长**。时长就是「留多长的历史」。弹速 7.2，原来主色带 0.22s / 尾槽 0.42s 拖出一两个世界单位，子弹早飞走了那截还亮着。现在主色带 0.07s（约半个世界单位、两三个弹身，读作速度线），尾槽 0.17s。

另外速原来还在后面挂两片柔光残影（`Ghost`），已撤 —— 速现在有自己的绿尾，那两片是同一件事说两遍。

**尾槽的颜色是用来认字的，所以混得比别的槽少**（`Pick(..., blend: 0.12)`，其余槽 0.35）：速是绿 `#3CB86A`、瞄是紫 `#9E47DB`。按 0.35 往混色偏，配上火就成了橄榄绿，那点识别度正好被冲掉。

顺带修了个一直在的 bug：`InkTheme.Accel` 这个绿**定义了却没接上** —— `Accent()` 少一条 `case CardId.Accel`，落到 `default` 的石墨灰去了。尾槽里速比瞄优先，所以带速的弹从来没拖出过绿尾。

### 4.2 命中三层（`FxBurst` → `InkBurst.Play`）

一次命中固定播三层，不叠三套爆炸：

1. **墨溅底**：始终有，白墨四帧，按混色 tint。
2. **元素层**：只播一个元素的四帧，优先级 `秒杀 > 域 > 火 > 冰 > 雷 > 毒 > 水 > 土 > 风 > 金 > 木`。被压掉的元素退化成**边上的色点**（最多 2 颗），所以三元素弹的命中仍然三色可辨。
3. **事件层**：`Kill / Stun / Push / Pierce` 单帧印章，没有事件就不出。

命中停顿（hitstop）只由事件层和重决定，元素层不产生停顿。

### 4.3 敌人身上的 DoT overlay（`InkDot.Sync`）

每种状态一层图，互不删，挂在敌人贴图上并**反向抵消敌人的呼吸缩放**，否则会跟着一起胀缩。

#### 分区：先划地盘，再画图

`BattleWorld.Enemy` 上是**四条独立的计时轨** —— `BurnTime`、`PoisonTime`+`PoisonStacks`、`SlowTime`、`HardTime`+`Hard`。它们互不排斥，所以**一只怪随时可能同时挂四层**。于是位置不是美术偏好，是硬约束：每层必须占住一块不重叠的区域，全堆在中间就会互相盖住，玩家数不清身上到底有几个状态。

坐标是怪的局部单位，脚底约 −0.45、头顶约 +0.45，常量集中在 `InkDot` 顶部：

| 状态 | 图 | 区域 | 常量 | 为什么在这 |
|---|---|---|---|---|
| 灼烧 | `burn_body_00`～`03` | 脚底窜起，火头到胸 | `Foot` −0.45，`BurnH` 0.62 | 火往上烧，从底部起最自然 |
| 冻 | `ice_crust_00`～`03` | 头肩往下长冰锥 | `Crown` +0.48，`CrustH` 0.58 | **和火正好反方向**，霜火那对才能同时读出来 |
| 中毒 | `dot_poison` ×1～4 | 身体两侧外缘上浮 | `SideX` ±0.30 | 走两侧让开中轴，中轴下半归火、上半归冰 |
| 缓 | `dot_ripple` | 脚下地面 | `Foot`，`SlowW` 0.42 | 只在地面，不跟身上任何一层抢 |
| 晕 | `dot_stun` | 头顶之上 | `Halo` +0.56 | 比冰锥更高一层 |
| 惑 | `dot_confuse` | 头顶之上 | `Halo` +0.56 | 和晕互斥，可共用 |

**冻和晕 / 惑能共用上半区，是因为三者本来就互斥**（都写 `Hard`，一次只能有一个）。真正必须错开的是「火 vs 冰」和「火/冰 vs 毒」这两组。

两个踩过的坑：
- **水纹的 sorting order 原来给的是 `order-1`，正好和怪身体同层**，谁盖谁由引擎决定。现在压到 `order-2`，明确在身体后面。
- **水纹原来给 0.62，大得像个站台**而不是减速，压到 0.42 才像脚边一圈。

#### 层数要砍

持续状态**一概不再叠柔光**（`PlayGlow` 全部撤掉）。冰锥 / 火焰 / 毒泡本身就是硬边图，外面再罩一圈雾正好把硬边泡软，而硬边是这套美术能立住的全部原因。

本体染色也从「冻 0.45 / 烧 0.45 / 毒 0.32」压到「0.20 / 0.22 / 0.18」，只留一点点「它变了色」。原来那么浓等于在图层之外再喊一遍同一件事，会把怪糊成一块色板；而且同时挂多个状态时本体**只能染一种色**，越浓越容易误导。

#### 回落

六层都是 `Mark(..., flat: true)` 走普通混合按原色画。图缺失时逐层回落到 `DotMarks` 运行时烘的火苗 / 水纹 / 漩涡基图（旧实现，靠 tint + 变换派生全部六种），所以删图不会开天窗，只是退回旧观感。

### 4.4 抽卡字面（`InkArt.OnCard`）

字图要在 CPU 上套宣纸卡框，所以 `Assets/Resources/Art/heap_*.png` 必须 `isReadable` 且不压缩；`Assets/Resources/Art/Vfx/` 下的只当贴图用，可读关掉、压缩打开 —— 但 §4.0 的平涂图（`fire_shot_*` / `burn_body_*`）是硬描边，和界面图标一样经不起块压缩，走 `flatVfx` 例外不压缩。分流在 `Assets/Editor/InkArtImporter.cs`。

## 8. 贴图预算

| | 之前 | 现在 |
|---|---|---|
| 磁盘 | 10.1 MB | 6.0 MB |
| 运行时贴图 | ~214 MB | 35.6 MB |

做了五件事：按目录分流导入设置、全部限到 256²、把压黑挪到离线、字图母版降到 256²、删掉 39 张早期按星级切图的遗留 `heap_*`（64 → 25）。

现在的 35.6 MB 拆开看：

| 分组 | 占用 | 为什么这么贵 |
|---|---:|---|
| 敌人 + 炮 + UI 图标（16 张） | 18.6 MB | 一刀切成了可读且不压缩，8 字节/像素 |
| `heap_*` 字图（25 张） | 12.5 MB | `InkArt.OnCard` 要在 CPU 上套卡框，必须可读不压缩 |
| `Vfx`（143 张） | 26.2 MB ⚠ | 见下，和上面这张表对不上了 |

**⚠ `Vfx` 那一行的 4.6 MB 现在不成立了。** 按 `.meta` 里 `DefaultTexturePlatform.textureCompression` 实测：143 张里**一张压缩的都没有**。也就是说「按目录分流压缩」这条规则**在旧图上从来没落地过** —— 导入器只在资源被重导时才跑，而这些 meta 后来被重新生成过（Library 重建之类），设置就丢了。要么批量重导一次让规则生效，要么按下面说的直接清掉。

拆开看：89 张 §4.0 平涂图 7.4 MB（**本来就该不压缩**），54 张旧柔光图 18.8 MB（**该压缩却没压**）。真正的大头是后者，而且体槽全员换成平涂图之后它们基本已经没人加载了。

§4.0 那 66 张平涂图不能压缩（硬边会崩脏点），所以要在**分辨率**上省。**按屏幕像素定分辨率，不要默认给 256²**：相机半高 7.4 → 全高 14.8 世界单位，1280px 屏上只有 86 px/世界单位，于是元素弹在屏上只有 12～22 px、词组弹 45 px、身上的状态层 54 px。256² 是过采样十倍。

现在切图统一输出**最长边 128**（`vfx_flat_slice.py` 的 `SIZE`），最大机型仍有 2 倍富余，这一组从 13.7 MB 降到 3.5 MB。

有个下限不能破：`InkSprites.Load` 用 `ppu = Max(tex.height, 64)` 建精灵，**贴图高一旦掉到 64 以下，精灵世界高就不再是 1.0**，§4.1 登记表里的 `Scale` 会连带缩水。水纹这种扁图（256×88 缩到 128 只剩 44 高）正好中招，所以 `MIN_H = 64` 给高度留了下限 —— 这两张宁可宽出 128 也不能矮过 64。

最大头已经不是字图，而是敌人和图标。其中真正需要可读的只有 7 张敌人图 —— `InkSprites.Flash` 靠 `GetPixels` 烘白色受击帧。炮和 9 张图标根本没人读像素，关掉可读能省 2.0 MB，但要在导入器里硬写文件名，加敌人时会静默踩坑，所以没做。**正解是把 `Flash` 改成材质染色而不是 `GetPixels`，那样 6.6 MB 一次全释放**，和字图的离线烘卡框是同一类改造。

`Resources/` 是整包打进去的，不要往里丢没有代码引用的素材。`Resources/Art/Vfx/` 下 144 个文件里，66 张 §4.0 平涂图全部有代码引用，其余 78 张多是早期的柔光试验产物 —— 体槽换成平涂图之后，`shot_fire` / `shot_ice` 这些旧单图已经没人加载了（只有 `shot_stun` / `shot_track` / `shot_accel` / `shot_heavy` 这几张环 / 尾 / 晕光槽的还在用），可以清一轮。

## 10. 加一个字要填的定义

```
字：

命中元素层：沿用哪一种 HitFx
DoT 标记：用哪颗、挂哪个位置
和谁同槽会互斥：

```

代码落点，不要在别处加长 if：

- `BattleWorld.ResolveHit`：只读 `ShotMods`，按第 3 节十步走
- `ShotLook.cs`：五槽优先级数组，加字就往数组里插一个 id
