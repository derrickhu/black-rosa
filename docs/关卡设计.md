# 墨弹防线 · 第一章关卡设计（20 关）

## 0. 为什么从 8 关扩到 20 关

原来 8 关的问题不是「短」，是**没有过渡**：

- 第一关就开一整排 6 个格子、给 3 个字、8 波怪、最后还压一个 70 血的关底。
  第一次上手要同时学「拖炮串」「选字」「放格子」「升星」「看波次」五件事。
- 开放行数只有 1 → 2 → 3 三个台阶，中间没有别的变化，每个台阶一跳就是三倍格子。
- 8 关只有 4 套波次编排（关 3–5 共用 `MidWaves()`、关 6–8 共用 `LateWaves()`），
  关 3 和关 5 的敌人构成几乎一样。
- 结果：内容很快见底，而每一关内部又塞得太满。

二十关的做法是把同样的内容**摊开成更细的台阶**，并且让几条递进线**互相错开**，
任何一关都只有一两件事是新的。

## 1. 三条递进线

| 线 | 从 | 到 | 步长 |
|---|---|---|---|
| 可放字的格子 | 2 格（第一排中间两格） | 18 格（三排全开） | 一关多 1 格 |
| 字池 | 1 个字 | 17 个字 | 一关多 1 个，成词的四对同关给 |
| 敌人 | 1 种纯墨杂兵 | 17 种，T0→T3 | 一关多 1 种 |

**格子按中间往两边开**，顺序是 `2, 3, 1, 4, 0, 5`（`StageCatalog.ColOpenOrder`）。
中间两列是敌人最密的地方，新手关只开这两格也立刻能感到「放字有用」；
要是从第 0 列开起，第一关的字会摆在几乎没人走的边上。

**成词的四对必须同关一起给**（击退 / 秒杀 / 连斩 / 万箭）。只发半边的那一关里，
那张牌就是张永远醒不了的废牌。所以字池的增量不是严格 +1，是 `1…9, 11, 13, 15, 17`。

## 3. 关 1 是真正的新手关

用户要的是「只开一行中的几个格子、字 1 个就够、怪 1–2 波就简单打完」。落地成：

- 开放格 `[2]`：只有第一排中间两格
- 字池 1 个（只有「分」）
- 2 波，7 只墨丁，总血 31.5
- **没有关底**
- 怪全走开放的那两列（2、3 列）。走到没开的列上虽然也打得死，
  但玩家会得到「我放了字却没反应」的错觉，第一关不该出现这种噪音

目标是三十秒内通关，只学「拖底下那串炮 → 选字 → 点格子」这三下，别的一概不教。
升星教学挪到关 2（那时有 2 个字、3 个格子，叠不叠才成为一个选择）。

## 4. 关底的排法

八只 boss，**一只管两关**：头一关单刷（看清它的机制），第二关带护卫（真考）。
关 1–2 没有关底。

出现顺序由**血量曲线**决定，不是由机制呼应决定。基础血乘上关卡系数
`t = 1 + 关序 × 0.08` 之后，每关关底波的总血量必须单调上升 ——
上表最后一列就是算出来的结果，`docs/prompt/runtime/check_stages.py` 会核这条。

代价是：boss 的机制往往**早于**同机制的常规兵出现。这个顺序反过来看是合理的，
而且是有意保留的：**先由 boss 演示一条规则，后面的关卡再把这条规则做成常规兵**。

| boss 先演示 | 常规兵后接手 |
|---|---|
| 墨囊（关 5）死了会裂成四只 | 双生（关 11）死了会裂成两只 |
| 铁桶（关 7）每发减 2、推不动 | 厚甲（关 12）每发减 1；爬子（关 7 同关）推不动 |
| 双首（关 9）半血加速 | 惊风（关 13）半血翻倍 |
| 牢头（关 11）免定身 + 奶周围 | 补墨（关 14）奶周围；镇守（关 17）免定身 |
| 鼓面（关 3）挡一发 | 铜盾（关 15）挡一发 |

关 17–20 是墨王四连，一路加码：单刷 → 带两只鼓面 → 带墨医 → 带双首 ×2 + 鼓面 ×2。

## 5. 代码改动

### 格子开放从「整行」改成「按格」

原来 `StageDef.OpenRows` 是一个整数，粒度只到整行，做不出「一排里先开两格」。
换成 `StageDef.OpenCells`（`int[]`，每行开放几格，长度就是开放行数）：

```csharp
new StageDef(0, "第一章 · 起笔", new[] { 2 }, Pool(1, ch), ...)   // 第一排中间两格
new StageDef(7, "第一章 · 束带", new[] { 6, 3 }, Pool(8, ch), ...) // 一排全开 + 二排中间三格
```

`BattleWorld` 多一张 `bool[,] Open` 和 `IsOpen(col, row)`。`OpenRows` 保留 ——
「按行往上扫」的那几处循环（`ApplyRows` / `ColumnHasMod` / `RebuildColumn`）
只需要知道最高开放行，没开的格子永远没有字，扫到那儿就够了。

改到按格判定的四处：`BattleWorld.PeekPlace`、`BattleView` 画格底、
`GameFlow.HandlePlaceClick`、`GameFlow.PaintPlaceHighlights`。

`HandlePlaceClick` 那处必须拦：`FieldLayout.TryCellAt` 只按**行**卡范围，
同一排里没开的格子照样点得到，不拦就会悄悄放进一个画成灰底的格子里。

### 胜利判定要能接受「没有关底」的关

`CheckEnd` 原来是 `BossKilled && AliveEnemies == 0 && 波次走完`。
关 1–2 没有 boss，`BossKilled` 永远是 false，这两关会卡在最后一波打不完。
改成先问这一关有没有关底：

```csharp
bool bossDone = !Stage.HasBoss || BossKilled;
```

`StageDef.HasBoss` 读最后一波里有没有 `EnemyIds.IsBoss` 的项。

### 三选一要能只发一两张

`RollOffer` 原来固定发 3 张，池子只有 1 个字时会发出三张一样的「分」，看着像出了 bug。
改成 `Min(3, 池子大小)` 张且强制去重；`DraftView.Bind` 按实际张数重新居中
（模板把三张按 `-200 / 0 / +200` 摆死了）。

顺带修掉原来那句 `if (pool.Count > 3)`：池子正好 3 个时它不去重，会发出重复项。

### 自动弹三选一的次数跟着格子数走

原来是「头两关 3 次、之后 2 次」，正好是反的 —— 头几关只开两三格，
弹 3 次没处放，等于在教「字可以乱堆」。改成
`Clamp(Stage.OpenCount / 3, 1, 3)`：关 1 一次，关 5 两次，关 9 起三次。

### 首页出征页重排

20 个印章排 **5 列 4 行**，印章从 164px 缩到 128px。
原来 8 关是 4 列 × 164px，那个尺寸排 5 行会超出内容区（1006px）。
印章上的「体力 N」改成**只在买不起的时候显示** —— 那才是要玩家做决定的时刻，
128px 的印章上再固定挂一行小字会糊成一团，平时的规则交给页脚那句说明。

### 存档兼容

`GameConstants.ChapterStageCount` 从 8 改到 20。
`MetaProgress.Normalize()` 里的 `Fit()` 会把旧存档的 `Stars` 数组补齐到新长度并保留旧值，
所以改这个数字不会打坏已有存档。

两处连带影响，都已确认无害：

- `ForgeCatalog` 的「暂未开放」判据是 `gate > ChapterStageCount * MaxStar`。
  上限从 24 涨到 60，但炮台数二级的门槛写的是 99，仍然大于 60，照旧显示「第二章开放」。
- `MetaProgress.ChapterCleared` 从「过第 8 关」变成「过第 20 关」。
  `NeedClear` 的皮肤和技能因此推后到真正的章末解锁，这正是本来的意图。

## 6. 已知问题

`StageCatalog.Chapter(chapter)` 的缓存忽略 `chapter` 参数
（`if (_cache == null) _cache = Build(chapter);`），所以 `Chapter(2)` 会拿到第一章。
现在全工程只走 `Chapter1`，没有暴露出来；第二章开工时要连这里一起改成按章缓存。

## 7. 核对

编译器管不了递进曲线：格子会不会中途缩回去、字池会不会突然掉一半、
新敌人有没有在「单独出场」那一波露过脸、关底波总血是不是单调上升 ——
这些错了游戏照样跑，只是曲线是坏的。所以有一个读源码的静态核对脚本：

    python3 docs/prompt/runtime/check_stages.py

它核这些：

- 20 关全部赋值，`StageDef` 里的 index 和数组下标一致
- 开放格数 / 字池 / 波数三条线单调不减，开放行数逐行增加，各排格子数不回退
- 关 1 只开两格、只有一个字、波数 ≤ 2、没有关底
- 只有前两关没关底，八只 boss 全部用上，关底波总血单调上升
- 第一个带颜色的常规兵不早于关 7，六只纯墨兵全用上，关 3 起每关最多引入一只新兵
- 25 个 `EnemyId` 都接了图、图在盘上、meta 齐全、`isReadable: 1`

**待你验收**：实机曲线。上面所有核对都是静态的，
「关 1 是否真能三十秒打完」「关 7 的铁桶在只有 7 个字的时候是不是墙」
必须进 Play 模式打过才知道。
